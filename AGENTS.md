# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- The repository uses npm workspaces; run `npm test` and `npm run build` from the root for the complete server/client validation.
- Treat `docs/deployment.md` as authoritative for Google Identity Services environment/origin setup and one-off database migrations.
- Conversation switching, stale-stream isolation, and the one authoritative chat-generation quota are behaviorally pinned in `client/src/stores/chatStore*.test.ts` and `server/src/middleware/auth.test.ts`.
- Immersive voice keeps browser recognition as its free path. `voiceCapture.ts` detects Brave up front (its exposed Web Speech constructor otherwise waits about 4–5s before the inevitable `'network'` error) and goes directly to the authenticated `/api/transcriptions` fallback; `allowServerFallback: false` still makes the barge-in probe non-metered. The fallback requires `OPENAI_API_KEY`, can incur usage charges, uses adaptive energy-based end of speech (quiet trailing words refresh activity; longer utterances get a longer pause), and caps recordings at 29.5s under the server's matching 30s `TRANSCRIPTION_MAX_DURATION_MS`; keep those limits and `docs/deployment.md` in sync.
- `speech.ts`'s `listenOnce` never uses `continuous: true` (unreliable in Safari/WebKit). It layers a multi-attempt turn over non-continuous recognition: normal silence commits at 1.6s, visibly unfinished text (trailing punctuation or a strong continuation word such as `and`/`the`/`to`) gets 2.4s, measured from the last result even across restarts, and an early `onend`/`no-speech` restarts after 80ms even when WebKit prematurely labeled an unfinished phrase final. Complete final results still resolve immediately; the whole-turn cap is 30s. See `speech.test.ts` before changing these heuristics.
- Barge-in is wired in `ImmersiveVoiceMode.tsx` and filtered by `utils/bargeIn.ts`: likely echo matching the current assistant reply is ignored, as is one unstable interim word unless it persists for 300ms; two distinct words or a final non-echo phrase interrupt immediately. The silent probe passes `allowServerFallback: false` and lives exactly as long as `avatarState === 'speaking'` (other mid-reply store updates must not restart it); when speaking ends it keeps listening if it already heard pending user speech (its final transcript must still pass the echo filter, which also treats a short reply-ending word such as `you` as echo), otherwise it is stopped so it cannot block the next idle listen. Open-speaker full duplex remains inherently echo-prone because `SpeechRecognition` exposes no AEC reference signal.
- Voice-mode replies are shortened/de-formatted via a `voiceMode` boolean threaded end-to-end: `ImmersiveVoiceMode` → `chatStore.sendMessage(content, { voiceMode })` → `POST .../messages/stream` body → `chatService.handleChatStream` → `Persona.getSystemPrompt(voiceMode)` (adds a "VOICE MODE" prompt layer, short/plain-prose/no-lists) and a lower `maxTokens` (`VOICE_MODE_MAX_TOKENS`) to `llmService.streamChat`. Voice mode (`latencyMode`) uses its own `GEMINI_VOICE_MODELS` list (Flash-Lite; free-tier Flash measured 10s+ TTFT in 2026-10) and `llmService`'s `streamChatHedged`: no same-model retries, a failure starts the next model at once, and a model with no token after `LLM_VOICE_HEDGE_MS` gets the next one raced alongside it (max 2 in flight, first token wins, nothing is cut off by timer). Text chat keeps sequential retry behavior. Gemini Lite models 400 on `reasoning_effort: 'none'` — `geminiReasoningEffort` sends `minimal` to them. `voiceLatency.ts` measures speech end → transcript → first LLM token → first TTS audio, publishing a content-free `voice-turn-latency` event and `voice.turn.latency` console metric in development builds only.
- Voice-turn timing: one `turnId` (`client/src/utils/voiceTrace.ts`, header `X-Voice-Turn`) ties the browser stage timeline (mic → STT → chat → per-chunk TTS → audio output, posted to `POST /api/metrics/voice`, which only accepts bounded numbers/enums so no content can be logged) to the server's `stt.transcribe`/`chat.turn`/`tts.synth` JSONL lines; `npm run voice-report -w server` joins them (`server/src/utils/voiceReport.ts`). The trace closes at playback drain (`chatStore`'s TTS state listener), on the `done` event if nothing is speaking, or as `aborted` when `resetSession` cuts the reply. New client stages: add a `trace.mark(...)` and, if it should be reported, a step in `computeSteps`.
- `TTS_PROVIDER` picks the engine behind `/api/tts`: `kokoro` (default) or `fishaudio` (hosted, `fishAudioTts.ts`; Kokoro is then never loaded). Both share `ttsService.synthesize`'s queue/timeouts/logging; the response `Content-Type` is per provider (WAV vs mp3/opus) and the client reads it. TTS is still Kokoro (`server/src/services/ttsService.ts`, sherpa-onnx-node) by default as of the 2026-09 voice-quality pass. Researched and rejected: `kokoro-int8-multi-lang-v1_0` (same dependency, 333MB→126MB, but int8 quantization measurably degrades Kokoro's prosody/timbre per real user reports); Piper voices via the same `sherpa-onnx-node` `OfflineTts` API (no new dependency, e.g. `vits-piper-en_US-libritts_r-medium-int8` at ~22MB, CC-BY-4.0) — smaller and license-clean for _that_ voice, but per-voice licenses vary wildly (some are CC-BY-NC-SA, some sit behind opaque legacy dataset license pages) and it's a different character voice, not a technical swap. Left as a `needs-decision` shortlist for the captain rather than guessed; re-verify current sizes/licenses against `k2-fsa/sherpa-onnx`'s `tts-models` release and each voice's own `MODEL_CARD` before revisiting, not this note alone.
- Kokoro inference runs through `server/src/services/ttsQueue.ts` (concurrency 1, max 8 waiting → 503 + `Retry-After`, 10s queue wait, 20s inference timeout; a queued job whose client disconnected never reaches the model). `GET /api/tts/health` is public and content-free; `ttsService` logs one JSON line per chunk with timings only — never log the text. `TTS_NUM_THREADS=auto` uses the cgroup CPU grant capped at 2 (1 on Linux when unreadable). The fp32 v1.0 model measured ~600 MB extra RSS — above a 512 MB Render instance.
- A flex child with `flex-1 overflow-y-auto` (e.g. `ChatWindow.tsx`'s transcript) also needs `min-h-0`, or it refuses to shrink below its content height and the scroll silently never clips — a classic flexbox trap. `ChatWindow.test.tsx`'s "scrollable history" suite guards this by compiling the project's real Tailwind utilities and asserting on `getComputedStyle` (not class-name substrings), since jsdom has no layout engine of its own.
- `personaStore.fetchPersonas()` is the only way `personas` (as opposed to `archetypes`) gets populated outside of opening/switching a conversation; `SwitchPersonaPage.tsx` calls it explicitly. Persona creation is intentionally disabled without deleting stored persona data.
- Production SPA refreshes depend on `vercel.json`'s final catch-all rewrite to `/index.html`; keep the `/api` and `/avatars` proxy rules before it so auth restoration owns protected-route redirects.
- `server/src/services/llmService.ts` tries Gemini then OpenRouter, each over its own env-configurable model list (`server/src/config/index.ts`). OpenRouter has no catch-all free-router alias (`openrouter/free` is not a real model id) — each free model needs its own `:free` id; verify current ones against `GET https://openrouter.ai/api/v1/models` before changing defaults, not the docs pages alone (LLM summarizers can invent plausible-looking free model names).
- Voice-reply (TTS) chunking is `client/src/utils/speechChunker.ts`'s `SpeechChunker` (fed per SSE token by `chatStore.ts`): a one-word opener is merged with the next sentence, the first chunk is cut at a clause past 80 chars, and each later chunk is capped at 1.6× the previous one (floor 60 chars) so it synthesizes while the previous plays. Retune only with `npm run bench-tts -w server` (real Kokoro timings on a streaming timeline), not by feel. Playback is `tts.ts` (re-exported by `speech.ts`): prefetch depth 2, every `/api/tts` fetch abortable (35s timeout, aborted on stop/new reply), one retry only for a network `TypeError` or 503 + `Retry-After`; decoded buffers are scheduled back-to-back on one shared AudioContext in `audioPlayer.ts` (unlocked on the first user gesture), with an `<audio>`-element fallback while the context is locked.
