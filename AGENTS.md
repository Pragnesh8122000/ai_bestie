# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- The repository uses npm workspaces; run `npm test` and `npm run build` from the root for the complete server/client validation.
- Treat `docs/deployment.md` as authoritative for Google Identity Services environment/origin setup and one-off database migrations.
- Conversation switching, stale-stream isolation, and the one authoritative chat-generation quota are behaviorally pinned in `client/src/stores/chatStore*.test.ts` and `server/src/middleware/auth.test.ts`.
- Immersive voice keeps browser recognition as its free path, but Brave's runtime `'network'` error falls back through `client/src/utils/voiceCapture.ts`'s `startVoiceTurn` to the authenticated, bounded `/api/transcriptions` endpoint — gated by its `allowServerFallback` param (default `true`; `ImmersiveVoiceMode.tsx` passes `false` for the silent barge-in probe so it never pays to transcribe a turn nothing was heard on). That optional path requires `OPENAI_API_KEY`, sends audio to OpenAI, and can incur usage charges; limits/privacy are authoritative in `docs/deployment.md` and guarded by the transcription route/tests.
- `speech.ts`'s `listenOnce` never uses `continuous: true` (unreliable/buggy on Safari/WebKit — results can stop without `onend`, or a session can run away). Instead it runs one non-continuous recognition "attempt" at a time and manages its own multi-attempt turn on top: a self-timed `SILENCE_COMMIT_MS` (1200ms) decides when a pause means the user is done, and any earlier `onend`/`no-speech` — an engine cutting the speaker off mid-word, the specific Safari failure this exists to fix — triggers a transparent restart (`RESTART_DELAY_MS`) that keeps accumulating into the same transcript. `maxMs` (default 20s) caps the whole turn, not one attempt. See the restart/no-speech/silence-commit tests in `speech.test.ts` before changing this.
- Barge-in (interrupting the persona mid-reply by talking over it) is wired in `ImmersiveVoiceMode.tsx`: while `avatarState === 'speaking'`, it silently starts a `startVoiceTurn` probe (no debounce) with an `onInterim` callback; the first non-empty interim calls `chatStore`'s `abortStream()` (which already stops TTS + invalidates the in-flight SSE stream) and switches to listening on that same session; the probe passes `allowServerFallback: false` so a silent probe (STT unsupported/rejected) never pays for a paid transcription call — see the line above. Full-duplex barge-in without headphones is inherently echo-prone (no separate AEC reference signal is available to the opaque `SpeechRecognition` API) — this is a known limitation, not a bug, if it mis-triggers on the persona's own voice through open speakers.
- Voice-mode replies are shortened/de-formatted via a `voiceMode` boolean threaded end-to-end: `ImmersiveVoiceMode` → `chatStore.sendMessage(content, { voiceMode })` → `POST .../messages/stream` body → `chatService.handleChatStream` → `Persona.getSystemPrompt(voiceMode)` (adds a "VOICE MODE" prompt layer, short/plain-prose/no-lists) and a lower `maxTokens` (`VOICE_MODE_MAX_TOKENS`) to `llmService.streamChat`. Text chat never passes this flag, so its prompt/length is untouched.
- TTS is still Kokoro (`server/src/services/ttsService.ts`, sherpa-onnx-node) as of the 2026-09 voice-quality pass — not swapped. Researched and rejected: `kokoro-int8-multi-lang-v1_0` (same dependency, 333MB→126MB, but int8 quantization measurably degrades Kokoro's prosody/timbre per real user reports); Piper voices via the same `sherpa-onnx-node` `OfflineTts` API (no new dependency, e.g. `vits-piper-en_US-libritts_r-medium-int8` at ~22MB, CC-BY-4.0) — smaller and license-clean for *that* voice, but per-voice licenses vary wildly (some are CC-BY-NC-SA, some sit behind opaque legacy dataset license pages) and it's a different character voice, not a technical swap. Left as a `needs-decision` shortlist for the captain rather than guessed; re-verify current sizes/licenses against `k2-fsa/sherpa-onnx`'s `tts-models` release and each voice's own `MODEL_CARD` before revisiting, not this note alone.
- A flex child with `flex-1 overflow-y-auto` (e.g. `ChatWindow.tsx`'s transcript) also needs `min-h-0`, or it refuses to shrink below its content height and the scroll silently never clips — a classic flexbox trap. `ChatWindow.test.tsx`'s "scrollable history" suite guards this by compiling the project's real Tailwind utilities and asserting on `getComputedStyle` (not class-name substrings), since jsdom has no layout engine of its own.
- `personaStore.fetchPersonas()` is the only way `personas` (as opposed to `archetypes`) gets populated outside of opening/switching a conversation; `SwitchPersonaPage.tsx` calls it explicitly. Persona creation is intentionally disabled without deleting stored persona data.
- Production SPA refreshes depend on `vercel.json`'s final catch-all rewrite to `/index.html`; keep the `/api` and `/avatars` proxy rules before it so auth restoration owns protected-route redirects.
- `server/src/services/llmService.ts` tries Gemini then OpenRouter, each over its own env-configurable model list (`server/src/config/index.ts`). OpenRouter has no catch-all free-router alias (`openrouter/free` is not a real model id) — each free model needs its own `:free` id; verify current ones against `GET https://openrouter.ai/api/v1/models` before changing defaults, not the docs pages alone (LLM summarizers can invent plausible-looking free model names).
- Voice-reply (TTS) playback is driven by `chatStore.ts`'s SSE `'token'` handler calling `speechText.ts`'s `takeSpeech`, which by default batches two sentences before flushing to the audio queue (for prosody continuity). Pass `minUtterances: 1` for a reply's first chunk when latency to first audio matters more than prosody — see `ttsHasSpokenFirstChunk` in `chatStore.ts`.
